# ADR-0008：license OR-MIT 维持 + M 系提交风格维持——双项偏差登记

- 状态：已裁决（Accepted，偏差登记）
- 日期：2026-10-22
- 关联：《系统开发指南》license 与贡献规范章；《Bedrock 磅基开发细则》编码规范章（提交规范）；workspace Cargo.toml；ROADMAP §七

## 背景

两项与指南/细则的既有偏差：

1. **License**：workspace 现为 `license = "Apache-2.0 OR MIT"` 双许可；细则规定 Apache-2.0 单许可。
2. **提交信息风格**：仓库自真链重建以来全部使用 **M 系中文活体式**（`M24-⓪-b ci 冒烟面对账：S8 补 virtio-net-pci 参数 + 自检计数 69→71`），带正文多段说明（根因/取证/对账）；指南编码规范要求 Conventional Commits 风格（`type(scope): subject`）。

两项偏差都是历史既成事实（v0.9.0 起全程一致），非近期引入。

## 决策

**双项维持，正式登记为偏差：**

1. **License 维持 `Apache-2.0 OR MIT`**：双许可在 Apache-2.0 条款兼容框架内（MIT 作为可选授权与 Apache-2.0 的专利条款不冲突），使用者可任选其一；单仓内 LICENSE 文件同时承载两份文本（现状已如此）。
2. **提交风格维持 M 系**：M 系中文活体式与 Conventional Commits 的差距（语言/格式）不影响其可审计性——本仓的变更追溯实际依赖 git log + devlog + 活体编号（t 系）三联，提交头的任务编号（M24-⓪-b）承担 Conventional Commits 中 type/scope 的定位职能，正文的信息密度（根因链 + 取证行 + 对账结果）高于规范式单行。
3. **细则修订提请**：下版指南/细则修订窗口，向规范侧提请两处并入——license 矩阵增补「Apache-2.0 OR MIT 为许可的双许可变体」、提交规范增补「任务编号前缀式（M 系）为等效风格」。提请未被采纳前，本 ADR 即偏差的唯一登记处。

## 理由

- **license**：双许可比单许可约束更宽（对下游更友好），且已存续十余个版本（全历史提交均在双许可声明下），收敛为单许可需要追溯确认全部贡献者——成本远超收益；细则的 Apache-2.0 要求在「OR MIT」下实质满足（使用者可选 Apache-2.0 路径）。
- **提交风格**：风格切换的收益（与指南文本一致）小于成本——全仓 300+ 提交的历史一致性强于风格统一性；且 M 系编号与 ROADMAP/工作日志/devlog 的任务编号体系已形成闭环引用（`M24-⓪` 在 ROADMAP §四是任务主键），改风格会断开这套跨文档引用链。
- 偏差登记制是本仓处理「现状与细则冲突」的低成本通道（ROADMAP §七已登记 4 项），本 ADR 将两项口头偏差转为正式登记。

## 影响面与回滚

- **影响面**：无代码/流程变更；docs/adr/README.md 索引 +1 行「偏差登记」类目；ROADMAP §七.1（提交风格）与 Cargo.toml license 行各加本 ADR 指针注释。
- **回滚**：若细则修订提请被拒且裁决反转——license 收敛单许可需法律面确认（全历史贡献者为同一人，单许可收敛可行）；提交风格切换为新提交起算、历史不改写。

## 替代方案

- **收敛 Apache-2.0 单许可**：否决——见上，追溯成本与下游兼容性收益不成比例；且「OR MIT」从第一天起就是仓库身份的一部分（README/LICENSE 全程一致）。
- **提交风格切换 Conventional Commits**（自 v0.25.0 起算）：否决——M 系编号体系的跨文档闭环（ROADMAP 任务主键 / devlog 批次 / t 系活体）价值高于风格合规；切换将产生两套风格并存的长过渡期，检索与审计成本双份化。
