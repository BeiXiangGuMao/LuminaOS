# ADR-0002：bedrock::vfs 越界——豁免登记 + M26 迁移两步走

- 状态：已裁决（Accepted）
- 日期：2026-10-22
- 关联：《Bedrock 磐基开发细则》依赖矩阵与组件边界章；《指标与规范手册》P2 阶段（CR-P05/06）；ADR-0001

## 背景

`bedrock/src/vfs/` 现状 8 文件 3762 行（fd 373 / fs 252 / lfs 1755 / mod 98 / mount 334 / node 156 / path 208 / ramfs 586），是全仓最大的单模块。细则把 VFS 归属划在 Meridian/Crystal 层（Bedrock 仅承载 abi/ipc/tlv 通信机制），bedrock::vfs 属结构性越界。

越界的历史原因：M13 起 VFS 骨架在真链上先于 Crystal 成形落地，此后 lfs（持久化）/ mount / ramfs / fd 持续增厚，与 kernel 的 `SYS_OPEN..SYS_MOUNT` 面（18-30/33-34 号）深度耦合。现状若无 bedrock::vfs，kernel 的文件面全部断供——**直接迁移等于阻断 P1 主线**。

## 决策

**两步走：先豁免登记、后整体迁移。**

1. **M24（登记步）**：在 M24-X1 lint-deps 白名单中登记 `bedrock::vfs` 为「结构性越界豁免项」，引用本 ADR；METRICS.md 登记「vfs 外移进度」观察项（行数与模块清单随季度对照）；**冻结新增**——vfs 模块自本 ADR 起只收 bugfix 与既有 syscall 语义维护，不收新功能面（新文件面需求一律排入 M26 Crystal 批次）。
2. **M26（迁移步）**：Crystal 文件系统首割（CR-P05）成形时，`vfs/` 整体外移出 bedrock。目标归属：代际槽容器与 fd 表底座随 crystal 域；挂载/注册策略面随 meridian 域；lfs/ramfs 物理面随 crystal 域。精确的 crate 归属在 M26 开工前出补篇（本 ADR 锁定方向与冻结令，不锁 crate 名）。

## 理由

- 「先登记后迁移」把结构性偏差变成**可见、可审计、有截止窗的债务**（lint 白名单 + 观察项 + 冻结令），而不是无期挂账；
- 冻结令是关键增量：不冻结则 M24-M26 间任何 VFS 需求都会继续加厚越界面，M26 迁移成本随时间上涨；
- 迁移押后至 M26 是风险最优解：Crystal 成形提供迁移目的地，且 ROADMAP §六已把「vfs 迁移押后至 M26」登记为 framekernel 迁移风险的缓解措施。

## 影响面与回滚

- **影响面**：M24-X1 白名单 +1 项；METRICS.md 观察项 +1；M26 批次预计为该季度最大单批（vfs 3762 行 + kernel `SYS_OPEN..SYS_MOUNT` 引用面 + 宿主 vfs 测试面搬迁）。
- **回滚**：登记步无代码动作，白名单撤销即回；迁移步保留旧路径 re-export 过渡窗（同 ADR-0001 纪律），单批可还原。

## 替代方案

- **a) M24 立即迁移**：否决——P1 主线（Meridian/Conduit 分发面）依赖现行 vfs 提供的 kernel 文件面，M24 强迁使两个主战场互相牵制，违背「每笔迁移带活体对账」的渐进纪律。
- **c) 永久豁免**（修订细则把 VFS 归属改判 Bedrock）：否决——细则的分层结论（通信机制 ≠ 资源管理）是框内核→服务化迁移的根基，永久豁免等于回到单体内核。

## 补篇：M26 迁移 crate 归属锁定（M26-计划 随附，2026-10-24）

正文第 2 条预留「精确的 crate 归属在 M26 开工前出补篇」，随 M26-计划 落盘锁定如下。方向性结论（fd/物理面随 crystal、策略面随 meridian）不变，本补篇仅锁 crate 名与连带裁决。

| 模块（行数） | 目标归属 | 依据 |
|---|---|---|
| vfs/fd.rs (373) | crystal::vfs | 正文「代际槽容器与 fd 表底座随 crystal 域」；GenerationalSlab 同域内聚，bedrock→crystal 豁免边随之清账 |
| vfs/fs.rs (252) | crystal::vfs | FileSystem 契约 + FsError + walk 为 FS 侧契约；实现者（lfs/ramfs/crystal 格式 v1）同域，meridian → crystal 方向正挂 |
| vfs/path.rs (208) | crystal::vfs | 纯路径词法面，fd/mount 共同消费的底座 |
| vfs/node.rs (156) | crystal::vfs | VnodeId/DirEntry/Metadata 契约类型，随 FileSystem 契约走 |
| vfs/lfs.rs (1755) | crystal::vfs | 正文「lfs/ramfs 物理面随 crystal 域」 |
| vfs/ramfs.rs (586) | crystal::vfs | 同上 |
| vfs/mod.rs (98) | 拆解不迁移 | re-export 门面 + FsError 定义：FsError 随契约入 crystal::vfs，门面随迁移删除 |
| vfs/mount.rs (334) | meridian::vfs | 正文「挂载/注册策略面随 meridian 域」；消费 crystal::vfs::{FileSystem, PathBuf, VnodeId} |

连带裁决：

1. **依赖边**：新增政策边 meridian → crystal（挂载策略消费 FS 侧契约）与 crystal → ostd（细则 4.3 并发模型指定 OSTD SpinLock）+ crystal → bedrock（BlockDevice 块契约，M26-F1 随格式 v1 先落）；`bedrock → crystal` 豁免与 `module_overreach(bedrock::vfs)` 随迁移清账。
2. **bedrock 零依赖收口（M26-V1-c）**：vfs 外移带走 vfs-lfs/vfs-mount/vfs-ramfs 三处 SpinLock 消费；剩余 block/ipc 两处 SpinLock 与 ipc FastPath SpscRing 在 bedrock 内联（无依赖等价实现），`bedrock → ostd` 豁免清账——bedrock 回归 ADR-0001 终态「零依赖通信与契约域」。
3. **过渡窗执行口径**：正文承诺的 re-export 过渡窗按两步兑现——V1-a 八文件整体迁 crystal::vfs（mount 暂驻过渡）+ `bedrock::vfs` 全量 `pub use crystal::vfs` 门面（kernel 零改道）；V1-b mount 策略面上移 meridian::vfs + kernel 引用面改道 + 门面删除。不做 bedrock → meridian 方向 re-export（会造出逆向边）。
4. **冻结令解除条件**：V1-b 落地即解除 bedrock::vfs 冻结令（模块已不存在）；新文件面需求此后走 crystal/meridian 批次，不再入 bedrock。
5. **kernel 引用面**：SYS_OPEN..SYS_MOUNT 与 fd 面改道 meridian::vfs（挂载策略）/ crystal::vfs（fd 底座与物理面）；宿主 vfs 测试面随模块搬迁，语义零改动。
6. **回归对账**：迁移批次 CI 全绿 + 冒烟自检计数不降（文件面既有 syscall 语义零回归）为迁移验收锚；每步可单 commit revert 还原。
