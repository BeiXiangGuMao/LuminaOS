# ADR-0004：framekernel 消解路径——混合态渐进，策略面外移

- 状态：已裁决（Accepted）
- 日期：2026-10-22
- 关联：《系统开发指南》框内核定义；《指标与规范手册》P1 阶段（M-P01/02）；ADR-0001/0002/0003；ROADMAP §七.3 既登记偏差

## 背景

细则定义的目标形态是**框内核 + 去特权服务**：内核只保留调度/内存/IPC/中断等最小机制，文件、显示、网络、电源等策略面全部在用户态服务进程。现状 kernel 16,870 行，除机制面（boot/mm/task/vmm/smp/swap/syscall）外还承载：

- **驱动旁路**：fb / vnet / kbd 内核态驱动（P5 要移除的旁路，ROADMAP §1.1 已定位）；
- **策略面**：shell（kernel::shell 四态机 + 命令分派）、显示面服务化残留（SYS_FB_TEXT 内核直画）、vfs 消费面。

激进拆分（一次性把驱动与策略面全部外移）在 M24 不可行：无用户态进程模型完备性（init/shell 刚在 M23-②③ 落地）、无服务间通信负载面（IPC 仅 FastPath 环）、P1 门禁（M-P01 分发预算）未达标——拆分的前提条件（分发面可用）本身就是 M24 的建设目标。

## 决策

**混合态渐进（方案 b）：机制留 kernel，策略面按「外移一个、活体对账一个」节奏逐里程碑外移 Meridian。**

- **M24**：dispatcher 首割（M24-M1/M2）——syscall 分发路由的策略面从 kernel 隐含逻辑变为 Meridian 显式实现（内核态热路径暂留，dispatcher 以同号域契约先行）；
- **M25**：Conduit 转换器面外移（Linux ABI 兼容策略离开内核域）；
- **M26-M28**：VFS 注册面（随 ADR-0002）、显示面（随 M28 合成管线）外移；
- **M31**：驱动用户态化起步（Vanguard 驱动框架 + 注入矩阵），内核态 fb/vnet/kbd 旁路按清单缩编。

**豁免条款**：迁移完成前，「services 全用户态」条款以 ROADMAP §七.3 登记的偏差形式豁免；每次外移批次 MUST 在 METRICS.md 登记外移清单行（组件/去向/活体证据），确保消解进度可审计。

## 理由

- 框内核消解是**多里程碑工程**而非单笔重构：细则的形态判定以「最终态」为准，渐进路径上的混合态是合法过渡，登记即可审计；
- 每笔外移带活体对账（t 系串口取证 + 宿主测试）是 M22 以来验证有效的回归纪律，一次性大爆炸式拆分无法执行该纪律；
- dispatcher 首割作为「第一割」有契约价值：它把「号域归属」这个后续一切外移的公共契约先冻结下来（号+版本位编码，细则 §3.2），后续外移模块按号域接入，避免各批次各自为政。

## 影响面与回滚

- **影响面**：跨 M24-M31 全部里程碑；kernel 行数预计从 16.9k 逐步回落（M24 不减——dispatcher 是增量外移，内核热路径保留双轨）；每批次回归成本 = 该批活体全谱。
- **回滚**：外移模块保留内核态直调路径一个过渡窗（双轨制），回归失败可单批切回；旁路缩编（M31）前任何外移都不删除内核机制面代码。

## 替代方案

- **a) 激进拆分**（M24 一次性外移驱动与策略面）：否决——前置条件（服务模型/分发面/IPC 负载）不成立，且违背活体对账纪律，回归面不可控。
- **c) 维持现状**（kernel 长期承载策略面）：否决——细则形态判定 P5 门禁（驱动自举 + 旁路缩编）不可达，等于放弃框内核路线。
