## 三、分项论证

### 1. 功能完备 —— 6/10

组件谱系广度已成形：指南指标族（Bedrock/Harbor/OSTD/Meridian/Conduit/
Crystal/Pulse/Vanguard/Prism/Mirror/Ripple/Loom/Cascade/Glyph/Weave/
Aurora）在 METRICS 全表均有承接行且活体在环，19 crate 单一职责分层
（依赖方向低→高单向，政策面 27 条机检承载）。功能深度以 t82 为界碑：
Alpine 官方静态 busybox 在裸机真跑全链（ELF 直载 → musl 初始化
arch_prctl/brk/mmap → fork 族 → applet 分发 → write(1) 取证 → exit_group
→ waitpid 收割），Linux 兼容路径从纸面绑定面（C-P01 BINDINGS）兑现为
执行面。深度未达项清晰在册：busybox 全功能覆盖度第一批只到 echo 级
（挂账⑦，覆盖度成像随转换层批次收敛）；多用户/多任务纵深单用户口径
（FS base per-CPU、XMM 用户态独占等随 t82 登记挂账）；网络 TCP 电气面
（挂账②）。判 6：广度对标谱系齐、深度首批活体落地，距「全功能」口径
尚有批次距离——不虚报。

### 2. 稳定性 —— 5/10

机制面齐备：S10-longrun 双面板 harness 在环（Panel A busybox boot-cycle
循环 + Panel B 1080p 显示 tick 循环，心跳/退出码/取证面完整），短窗实证
当轮全绿（A 双拍均值 22s 全口径绿 / B 30s 窗 2688 tick、168 心跳严格
单调、零 FAULT）；82/82 自检门禁基线每提交在环；crystal crash-fs 1000
断点逐扇区扫描两态一致（位翻转 96 点全检出）提供持久层故障注入证据。
长时程证据诚实地缺位：正式 24h busybox / 72h 1080p@60 门禁记录待真机
窗口（风险登记册既定裁决：TCG 回归基线制——机制面在本轮兑现，绝对
时长记录挂账）；t73 设备级 RX 死亡窗口三形态在录（环境时序面定性，
冷却脱窗复跑口径三度实证）。判 5：判稳机制与短窗证据在环，长时程
证据链是 5→7 的唯一缺口——挂账如实、不为短窗绿虚报长稳达标。

### 3. 性能效率 —— 5/10

基准登记口径完备（METRICS 表基准挂接约定 + 各族行）：AF-P01 宿主框架
冷启动基准桩实测 0.18ms（满载 16 应用 × 48 能力），距 120ms 预算余量
663 倍且带回归哨兵闸；M-P01 派发热路径宿主微基线（100k 均值 + 1k p99
防退化）；B-P01 双核双环 1000 轮 2.2μs/round TCG 参考基线；M4 TSC 校准
（裸机 ≈ 3.15 GHz）后页表遍历 21.7 ns/次、协作切换 0.64 μs/次。绝对
门禁未达项全在册：SPEC 表 2-2 的 B-P02/B-P03 绝对预算、M-P02 端到端
2.5μs、显示刷新率时限类指标均待环境 B（真机）实测——TCG 数值仅作
回归基线的既定裁决如实执行（1080p@60 在 TCG 下不可实测，S10 Panel B
fps=89.6 为合成口径信息面）。判 5：参考基线在册 + 口径闸在环，绝对值
证据链 5→7 缺口 = 真机窗口。

### 4. 安全健壮 —— 6/10

三面在环：① 能力模型纵深——vanguard 能力四相（授予/派生收窄/撤销/
使用）+ V-P05 注入矩阵全枚举（越权派生/撤销后使用/未安装槽/重复撤销
四相 × 不变式 + derive 链传播全枚举，库本体零改动实现零缺陷逃逸）+
aurora perm 四相承接（声明 schema 闸 → 承接授予 → 检查显形 → 撤销显形）
+ AF-P03 生命周期非法迁移拦截 100%；② 故障面纪律——weave WE-P02 断电
注入四相恢复不变式（活跃指针胜出/回滚不残留/撕裂残槽显形）+ crystal
crash-fs 两态一致 + 全库 fail-visible 显形纪律（错误显形不静默，t73
取证在录为范式）；③ 语言面纪律——unwrap/expect 全仓 deny（生产路径
零 panic 载体）+ unsafe 台账 116 处允许层 + 10 crate 级 forbid(unsafe_code)
+ MMU 域白名单/MMU 双防线。未达项：进程间隔离纵深（单用户口径三项
挂账随链）、harbor C ABI 指针层（挂账⑥）、网络栈安全面（TCP 缺位
随挂账②）。判 6：能力与故障注入双证据链在环，隔离纵深 6→8 缺口 =
多用户批次。

### 5. 工程治理 —— 8/10

机检治理密度为五维之最：CI-OK 11 阶段全机检（fmt/clippy 双面/build/
test/doc + IDL 漂移字节级闸 + 依赖矩阵/unsafe 台账机检 + kernel 双阶段
+ 裸机冒烟 + 报告），fail-fast 每提交在环；政策面 27 条依赖边零违规
（台账先行纪律——新边先登记后落地）；宿主测试 397 例/38 套件 + 冒烟
82 相活体；文档体系四层（ROADMAP 里程碑账本 / METRICS 指标映射 /
CHANGELOG 版本谱系 / ADR-0001~0008 决策档案）+ 挂账随行复核纪律 +
风险登记册 + 偏差登记（§七 五项如实受审）；作业纪律（单件事提交、
门禁全绿才推送、推送后 API 回环核实、每里程碑收尾对账）；全历史
修史（身份统一保序保时，树字节级不变，§七 备查登记）。未达项：外部
评审/社区流程缺位（单人仓库形态——治理闭环内生于工具链而非外部制衡）、
细则 PDF 逐条对账（挂账⑤）。判 8：机检面近满档，外部制衡面是 8→9
的结构性缺口。
